## 5. Evaluador (`qa/s_tiempo_eval.py`)

Función pura `evaluate(part_dir) -> verdict`, ciega a mutantes y a `op_id` opacos (lee solo `part_dir / "samples"` y `schema`, `id`, `kind`, `build`, `both`, `params`, `identity` de `part_dir / "manifest.json"`, sin abrir `injection.json` ni `part.json`, F0.3-0 v4 §5.2, §6.1(12)). Precedencia: algún `fail` → `1 FALLA`; si no, algún `missing` → `2 INCONCLUSO`; si todo `pass` → `0 PASA`.

- **Conversión de fecha (`parse_date_minutes(num, prefix="")`, cierra N2, N13, N18):** para cada `k` en `(f"{prefix}year_n", f"{prefix}month_n", f"{prefix}day_n", f"{prefix}hour_n", f"{prefix}minute_n")`, comprueba que `k in num`, que `v = num[k]` es `int` o `float` (no `bool`), `math.isfinite(v)` y `v == math.floor(v)`, convierte `iv = int(v)` y devuelve `datetime(iv_y, iv_mo, iv_d, iv_h, iv_mi, tzinfo=timezone.utc).timestamp() / 60.0` (cualquier violación o `ValueError` marca el check como `fail`). La expectativa desde `(target_date_min, date_set_tick_ms)` con factor `1.0` es `expected_min(t_ms) = target_date_min + ((t_ms - date_set_tick_ms) / 60000.0) * 1.0`.
- **Contrato funcional de `check_env_ready(target, read_outcome, last_set_outcome, last_date_set_outcome=None) -> tuple[bool, str]` (cierra N3, N11, N14, N16, N17, N20):** evalúa en este orden estricto de prioridad:
  1. `not validate_env_request(target)[0]` → `(False, "invalid_target")`;
  2. `read_outcome.status != "done"` o `last_set_outcome.status != "done"` o faltan cualquiera de las 24 claves de `read.nk` (o `last_date_set_outcome` no es `None` y su `status != "done"`) → `(False, "read_failed")`;
  3. `read_outcome.frame_done < last_set_outcome.frame_done` o `read_outcome.done_ms < last_set_outcome.done_ms` o `read_num["env_set_count_n"] != set_num["env_set_count_n"]` o `read_num["tick_ms"] < set_num["tick_ms"]` o `read_num["set_tick_ms"] != set_num["set_tick_ms"]` → `(False, "stale_env_read")`;
